# ULTIMATE: аудит и план реорганизации

Документ по ТЗ «Упрощение UX и реорганизация ULTIMATE». Сначала аудит и план, затем (ниже, по мере работы) журнал изменений.

## 1. Аудит текущей архитектуры

**Стек.** Без сборки: `index.html`, ES‑модули в `src/`, стили в одном `src/styles.css`, IndexedDB через `src/db.js` (все коллекции в памяти, запись с дебаунсом, подписка `db.subscribe` перерисовывает текущую страницу), PWA (`sw.js`, cache‑first, `VERSION`), зашифрованная синхронизация (`src/sync.js`, слияние по `updatedAt` + tombstones), помощник Claude (`src/ai.js`, `src/ai-panel.js`), модульные страницы (`src/blocks.js`), послания (`src/motivation.js`).

**Маршруты** (`src/app.js`, `PAGES`): today, calendar, goals, projects, shadow, people, habits, journal, learning, notes (алиас books), kb, health, workouts, nutrition, sleep, finance, settings — 17 разделов, одна плоская лента в сайдбаре, 5 вкладок внизу на телефоне + «Меню».

**Компоненты.** `ui.js`: `modal/field/formRow/formData`, `toast`, `on` (делегирование), `dateNav`, `checkBtn`, `ring/barChart/lineChart`, `emptyState`. `blocks.js`: `composeBlocks`/`applyLayout`, режим редактирования, кнопка‑шестерёнка в каждом `.page-head`. `fx.js`: палитра ⌘K с быстрыми действиями (задача, заметка, вода, занятие), конфетти. `ai-panel.js`: плавающая кнопка всегда, панель справа.

**Сущности и дубли.**

| Что хранится | Где | Проблема |
|---|---|---|
| Задачи | `tasks` | базовая модель; нет связи с человеком, источника, времени, чек‑листа |
| Задачи от CEO | `shadowTasks` | отдельная система: свои поля (`deadline, context, result, receivedAt`), свой список, своя модалка; дублируется в «Сегодня», календаре, помощнике отдельным кодом |
| Обязательства «я обещала / мне обещали» | `commitments` | третья система задач, свои модалки и агрегации |
| Заметки из источников | `notes` | базовая модель (kind, sourceType, теги) |
| Идеи | `ideas` | отдельная база со своим статусом/оценкой |
| Рекомендации и заметки о CEO | `shadowNotes` | отдельная база; флаг `quote` живёт только здесь |
| Журнал контактов | `contacts` | по сути заметки о встречах |
| Журнал проекта | `projects[].log` | встроенный массив записей |
| Сон | `sleepLogs.hours/energy` и `checkins.energy` | энергия хранится в двух местах |
| Вода | `dayLogs.waterMl` и привычка «Вода» | одно и то же отмечается дважды |
| Тренировка/занятие | `workouts`, `studySessions` + привычки | то же |
| Прогресс проекта | `projects.progress` (ручной) | при наличии задач считается отдельно, но карточка показывает ручное число |

**UX‑проблемы, подтверждённые кодом.** Статистика «0» первой на страницах Shadow, Люди, Проекты, Привычки, Цели (блоки `.grid-3/.grid-4` из `.stat`); три равнозначные кнопки в шапке Shadow; `.chips` с горизонтальной прокруткой на 360 px; шестерёнка «Настроить» в каждой шапке; плавающая кнопка помощника всегда, поверх нижней панели; «чемпион» и цитаты без выключателя; при прямом открытии `#/shadow` до `db.ready` страница пустая, а `document.title` = «ULTIMATE» (вспышка).

## 3. Модели данных: было → стало

**Задача `tasks`** (единая): `title, notes, date, time?, priority, done, doneAt, projectId?, streamId?, goalId?, personId?, source: manual|ceo|promise|project|meeting|assistant, direction: mine|theirs (для обязательств другого человека), tags[], estimateMin?, recurring?, checklist[{id,title,done}], focusDate?, timeless?, result? (что ответила), receivedAt?`.
- Задача от CEO = `source: ceo, personId: <CEO>`. Видна в Shadow, Плане, календаре, карточке человека, проекте.
- «Я обещала» = задача `source: promise, personId, direction: mine`. «Мне обещали» = `direction: theirs` (не попадает в мой список дел и фокус, видна у человека, в календаре и Shadow как ожидание).

**Заметка `notes`** (единая): `type: note|idea|recommendation|meeting|insight|project-log, title, body, date, tags[], personId?, projectId?, goalId?, learningItemId?, pinned, quote (показывать как цитату), + поля источника (sourceType, sourceTitle, sourceAuthor, sourceUrl, rating, kind), + поля идеи (status, impact, effort), + поля встречи (meetingKind, next)`.
- Рекомендация CEO = `type: recommendation, personId: <CEO>`; заметка о работе с ним = `type: note, personId`; итог встречи/контакт = `type: meeting, personId`.

**Человек `people`**: без изменений; CEO — человек с `type: ceo` (создаётся автоматически при миграции, id `person_ceo`). `settings.ceoPersonId` для явного выбора.

**Событие `events`**: + `personId?` (встреча с человеком → «следующая встреча» в Shadow и карточке).

**Привычка `habits`**: + `auto?: { kind: water|workout|study|sleep|steps|task, keyword? }` — выполнение считается из фактических данных дня.

**Чек‑ин**: `checkins` — единственный источник energy/mood/confidence/stress; `sleepLogs.hours` — единственный источник сна. Поле `sleepLogs.energy` больше не пишется (читается как запасное).

**Настройки**: `tone: neutral|support|business` (по умолчанию neutral), `quotes: false`, `preset: minimal|work|health|full|custom`, `modules: {pageId: on|off|hidden}`, `mobileTab` (закреплённый раздел), `aiFab: true`, `eveningFrom: 18`, `ceoPersonId?`, `unifyV`.

Старые коллекции `shadowTasks, shadowNotes, commitments, contacts, ideas, books` остаются в базе и в экспорте, но интерфейс их не читает и не пишет.

## 4. План миграции

Выполняется при каждом старте (`runMigrations()` после `db.ready`), а также после импорта JSON и после слияния синхронизации. Идемпотентна: id новых записей детерминированы (`ceo_<id>`, `commit_<id>`, `shadow_<id>`, `idea_<id>`, `contact_<id>`), запись не создаётся, если уже есть или была удалена (есть tombstone). Старые записи не удаляются — поэтому старый JSON импортируется без потерь, а устройство со старой версией приложения не ломает данные: его записи подхватятся при следующем запуске новой версии.

1. Если есть `shadowTasks/shadowNotes` и нет человека `type: ceo` → создать `person_ceo` «CEO».
2. `shadowTasks` → `tasks` (`deadline→date, context→notes, source: ceo, personId`).
3. `commitments` → `tasks` (`due→date, source: promise, direction`).
4. `shadowNotes` → `notes` (`advice→recommendation`, `note→note`, `quote` сохраняется, `personId`).
5. `ideas` → `notes` (`type: idea`, статус/оценки/проект сохраняются).
6. `contacts` → `notes` (`type: meeting`, `kind→meetingKind`, `next`).
7. Старые `notes` без `type` → `type: note`.
8. `settings.unifyV = 1`.

**Риски.** (а) Два устройства мигрируют независимо → одинаковые id, слияние по `updatedAt` выбирает одну копию с тем же содержимым — дублей нет. (б) Удалённая мигрированная запись не возродится благодаря проверке tombstone. (в) Помощник со старыми инструментами `add_shadow_task` — инструменты переписаны на общие модели. (г) Раскладки `settings.layouts` для страниц, которые перестроены, сбрасываются для этих страниц (ключ `layoutsV`).

## 5. План реализации

1. **Аудит** — этот документ.
2. **Быстрые UX‑правки**: тон/цитаты выключены по умолчанию; помощник без ключа скрыт; плавающие элементы учитывают нижнюю панель; заголовок и экран маршрута с первого кадра; фильтры не обрезаются.
3. **Унификация данных**: `model.js`, `migrate.js`, обновление всех читателей/писателей (today, calendar, people, shadow, ideas, motivation, ai, fx).
4. **Навигация и захват**: группы и свёртывание, мобильная панель 4 + «+», `capture.js`, меню `•••`, пресеты и модули в настройках.
5. **Перестройка экранов**: Сегодня → План → Shadow → Люди → Проекты → Заметки/База → Привычки → Обучение → Рефлексия → остальные (пустые состояния, строка статистики).
6. **Проверка**: desktop, 390 и 360 px, планшет, обе темы, клавиатура, импорт старого JSON, экспорт, синхронизация, PWA, прямое открытие маршрутов. Скриншоты.

## 6. Журнал реализации (19 ноября 2026)

### Реализованные изменения
- **Данные.** `src/model.js` (единая логика), `src/migrate.js` (перенос в единые модели), `tasks` и `notes` расширены (см. SCHEMA.md). Shadow, Люди, План, календарь, главная и помощник читают только `tasks`/`notes`/`events`. Старые коллекции остаются в базе и экспорте.
- **Навигация.** Группы в сайдбаре сворачиваются; на телефоне 5 интерактивных элементов внизу: Сегодня · План · «+» · Работа (хаб с переключателем проекты/люди/Shadow) · Ещё. Третью вкладку можно заменить своим разделом. Алиасы `#/goals`, `#/calendar`, `#/books` сохранены. Заголовок и каркас нужной страницы рисуются до загрузки базы (вспышки «Сегодня» нет).
- **Глобальное «+».** `src/capture.js`: текст → тип (задача/событие/заметка/расход-доход/активность) угадывается, контекст раздела подставляет человека, проект, дату; «Подробнее» раскрывает поля; клавиша `N`; палитра ⌘K ведёт туда же.
- **Сегодня.** Порядок по ТЗ; следующее событие; фокус с встроенным быстрым добавлением и компактной строкой «Фокус дня пока не выбран»; чек-ин свёрнут до «Как вы сегодня? 1–5», разворачивается в сон/энергию/настроение/уверенность/заметку; «Требует внимания» (дедлайны + просрочка); вечерняя рефлексия с часа из настроек; карточки модулей только для используемых и включённых. Сетка: если в колонке меньше двух блоков — одна центральная колонка.
- **План.** Сегодня / Неделя / Все задачи / Цели (+Визуализация); на телефоне полоска дней + список, не семь колонок; типы элементов различаются иконкой и подписью; строка сводки вместо трёх карточек.
- **Shadow.** Представление по CEO (`people.type = 'ceo'`): следующая встреча, строка «N открытых · просрочено · встреча через…», одно поле «Записать после разговора…», одна кнопка «Записать» с выбором типа, вкладки Обязательства / Встречи / Заметки. Цитаты — флаг `quote` на заметке, показываются только при включённых посланиях.
- **Люди.** Лёгкий CRM на задачах и заметках: обязательства в обе стороны, последний контакт, следующая встреча, последние заметки, фильтр «Все люди · Фильтр» на телефоне.
- **Проекты.** Прогресс из задач; пустое состояние с одним сценарием; активные → следующие действия → дедлайны → без активности → аналитика в раскрытии; заметки проекта.
- **Заметки / База знаний.** Единая лента всех типов, универсальный поиск, перенос заметки в страницу базы знаний; идеи и рекомендации — типы заметок.
- **Привычки.** Сегодня → неделя → серия → статистика по раскрытию; автоматическое выполнение из воды, тренировок, занятий, сна, шагов, закрытых задач.
- **Обучение, Рефлексия, Здоровье, Тренировки, Питание, Сон, Финансы.** Вкладки/быстрый режим, без нулевых карточек, список и ввод выше аналитики, единые источники сна и энергии.
- **Помощник.** Кнопка только при ключе; выключается в настройках; на телефоне панель во весь экран, кнопка над нижней панелью; инструменты пишут в общие модели.
- **Тон и шум.** `tone: neutral` по умолчанию, послания выключены, «чемпион» и конфетти только в поддерживающем режиме. Контраст вторичного текста повышен, подписи ≥ 12.5 px, элементы касания ≥ 44 px, видимый фокус, `aria-label`, safe-area.
- **Настройки.** Интерфейс: тон, послания, час рефлексии, кнопка помощника; наборы модулей (Минимальный/Работа/Здоровье/Полный/Пользовательский), состояние каждого раздела, третья вкладка, кто показывается в Shadow.

### Миграции
`runMigrations()` при старте, после импорта и после слияния синхронизации: `shadowTasks → tasks (ceo_)`, `commitments → tasks (commit_)`, `shadowNotes → notes (shadow_)`, `ideas → notes (idea_)`, `contacts → notes (contact_)`, `notes.type`/`tasks.source,direction` по умолчанию; `settings.unifyV = 1`. Проверено: старый JSON с `shadowTasks/shadowNotes/commitments/ideas` импортируется, записи появляются в Shadow/Плане/Людях с исходной датой создания, повторный запуск ничего не дублирует, старые записи сохраняются.

### Результаты проверки
- Все маршруты (включая `#/goals`, `#/calendar`, `#/books`) открываются без ошибок в консоли на 1280 px и 375 px; заголовок документа соответствует маршруту с первого кадра.
- 375 px: нет горизонтальной прокрутки страницы; нижняя панель — 5 элементов; фильтры переносятся или сворачиваются в «Фильтр».
- Светлая и тёмная темы — ок. Клавиатура: вкладки, меню «•••», строки списков с `role=button` реагируют на Enter/Space; фокус виден.
- Окно «Записать»: «Созвон с командой завтра 15:30» → событие на завтра 15:30; «Кофе 350 руб» → расход 350 ₽; Enter сохраняет, Esc закрывает.
- Service worker: в встроенном браузере Claude не регистрируется (ограничение среды), на GitHub Pages работает; `VERSION` поднята до `lifeos-v21`, новые файлы добавлены в `APP_SHELL`.

### Известные ограничения
- Журнал проекта (`projects[].log`) остался встроенным массивом, тип заметки `project-log` зарезервирован, но не используется.
- Помощник с настоящим ключом Claude не проверялся (ключа нет); проверена только отправка в общие модели.
- Раскладки страниц (`settings.layouts`) для перестроенных страниц могут ссылаться на старые id блоков; при странностях — «•••» → «Настроить страницу» → «Сбросить».

## 7. Сигналы (19 ноября 2026)

Новый раздел «Сигналы» в группе «Знания»: источники новостей → лента → сводка помощником.

- `src/signals.js`: мост к сети (локальный `serve.py` → напрямую → публичные прокси; `quick`-режим для перебора адресов при поиске ленты), разбор RSS 2.0 / Atom / RDF / JSON Feed / ответа rss2json, Telegram-каналы через `t.me/s/<канал>`, поиск ленты на сайте (`<link rel=alternate>` и типовые пути), хранение записей с детерминированными id, очистка, сборка входа для сводки (равномерно по источникам, ≤ 11 000 символов под контекст локальной модели), промпт сводки.
- `src/pages/signals.js` + `src/css/signals.css`: вкладки Лента / Сводка / Источники, фильтры, действия с записью (открыть, сохранить, в заметки, в задачу), сводка с потоковым выводом и историей, поле «Что мне важно», управление источниками и способом загрузки.
- `src/ai.js`: `askPlain()` — запрос без выжимки данных и без инструментов (Ollama и Claude), заголовки и сводка в контексте помощника на странице раздела, подсказки.
- `serve.py` + `start.command`: локальный сервер вместо `python3 -m http.server`, со статикой и загрузчиком лент; старый сервер на порту заменяется автоматически.
- `src/db.js`: коллекции `signalSources`, `signalItems`, `signalDigests` (синхронизируются как все), настройки `signals*`.
- Главная: карточка «Сигналы» (выдержка сводки или 3 свежих заголовка). `sw.js` → v23.

Проверено в браузере: добавление сайта (vc.ru → найдена `/rss`), RSS (The Verge, Atom), Telegram (`@durov`); лента на 1280 и 375 px без горизонтальной прокрутки; сводка локальной моделью qwen2.5:14b за ~27 с по 20 записям; карточка на главной. Ограничение: публичные прокси в момент проверки отвечали 522, кроме rss2json; надёжный путь — приложение через `start.command`.


Дополнение: service worker теперь не перехватывает пути `/__*` (мост и проверка локального сервера), а ответы с `Cache-Control: no-store` не роняют запрос. Мост отдаёт CORS-заголовки, и приложение, открытое с сайта, пробует сервер на Mac по адресу 127.0.0.1:8765 (браузер может это запретить, тогда остаются публичные прокси).
